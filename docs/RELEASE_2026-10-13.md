## API 與相容性

- 新增 `GET /api/events/[id]/registrations`：401 未登入、404 活動不存在、403 未獲授權。
- `GET /api/admin/roles?organizationId=...` 新增可管理 `organizations` 與目前選中的 `organization`；沒有 query 時優先自己的分會，否則第一個所轄分會。
- `POST /api/admin/roles` 必須包含 `organizationId`、`memberId`、`role`。前後端一併部署；舊 payload 缺 organizationId 會被拒絕。
- `DELETE /api/admin/roles/[roleId]` 依該權限的實際 scope 重新驗證，不再固定登入者分會；仍不可由此撤銷自己的角色。
- 分會內只授予 `CLUB_OFFICER`／`CLUB_FINANCE`／`CLUB_VICE_PRESIDENT`／`CLUB_PRESIDENT`，不開放透過前端自授區級或全域角色。
- 本次程式沒有新增 Prisma model、DB migration、環境變數或正式資料異動；沿用 Jerry 已上線的資料結構。
