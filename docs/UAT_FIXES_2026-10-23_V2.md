## 推 main 與部署／DB 是不同狀態

- 推送可能觸發既有 Amplify 自動部署；**GitHub main SHA 不等於實際服務 SHA**，仍需 Jerry 回報執行環境與部署結果。
- 本次沒有直接操作正式 DB、Secrets、IAM、Apple 金鑰或商店送審。
- 新增 `20261023110000_event_tags` migration，只為 Event 加預設空陣列的 TEXT[] 欄位，不回填猜測標籤、不改會員資料。
- **舊 DB 相容保護**：Prisma schema 的 `Event.tags` 暫以 `@ignore` 排除一般 ORM 讀寫；只有 `event-tags.ts` 在確認欄位存在後，以綁定參數 SQL 存取。
- migration 前，API 回 `tagsAvailable=false`、標籤選擇暫停；既有讀取／無標籤發布／編輯／報名仍可用。帶非空標籤的寫入回 503 並回滾，不遺失輸入也不建立半筆活動。
- migration 完成後，下次查詢自動啟用標籤，不需重啟；既有活動預設空標籤。**不要先移除 `@ignore`**，否則未遷移環境可能再次因缺欄位失敗。
