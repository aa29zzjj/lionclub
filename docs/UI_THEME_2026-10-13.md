# 日夜主題、個人檔案與 App UI 交接（2026-10-13）

## 完成內容

- 「我的檔案」新增系統／淺色／深色切換，預設跟隨裝置外觀。設定使用 `lion-theme` 存在目前裝置的 localStorage；重新整理保留選擇，同網域分頁會同步。無法使用 storage 時，仍可在當次開啟期間切換。
- 頁面、卡片、文字、次要文字與邊框改由 CSS 色彩變數控制；淺色採暖白底、白色卡片與深藍字，深色保留深藍金色品牌。品牌會員證／資歷卡維持深藍底與亮色文字。
- 分開金色文字與按鈕底色。新純色主按鈕使用 `bg-lion-action` 搭配 `text-lion-navyDeep`；不要把淺色版較深的 `text-lion-gold` 色值直接拿來當按鈕底。
- 登入、註冊、重設密碼、好友、活動、資歷、通知與管理頁皆沿用主題；舊半透明白底／白邊框提供淺色相容層，之後新元件應直接用語意 token。
- 手機、生日空值改為「尚未填寫 · 補上」，點按後進入編輯並聚焦對應欄位。入會年月由幹部管理，空值顯示「待幹部補登」；會員編號空值顯示「待系統編號」。
- 幹部入口整併為有圖示、說明與箭頭的「幹部工具」卡片，依既有管理角色顯示。一般會員不顯示此卡片，API 的權限判定保持有效。
- 個人資料載入失敗提供重試；儲存時禁用重複提交並顯示儲存中，網路失敗保留編輯內容。未上傳頭像時改送空字串，對齊現有 API 的欄位驗證；自訂職稱也會保留在編輯選單中。

## 主題維護

| `lion-page` / `lion-canvas` | App 內頁／桌面外圍背景 |

`layout.tsx` 在初始畫面繪製前套用偏好，`ThemeProvider` 處理切換與系統外觀變更。`color-scheme` 也會更新，讓日期欄位等瀏覽器原生控制項配合主題。`theme-color` 配合選擇更新瀏覽器介面色彩。

## 為 iOS／Android 準備的 UI

- viewport 加入 `viewport-fit=cover`，App 容器加入頂／左右安全區；底部選單與無選單內頁處理底部安全區。登入頁與 QR 彈窗也納入安全區。
- App 容器使用 `100dvh`，並保留 `100vh` fallback；QR 彈窗在較矮畫面可捲動。
- 主題切換、補填入口與底部選單至少 48 CSS px 高；底部文字提高到 11px，選中狀態同時使用淡色背景與 `aria-current`。
- 手機版表單文字至少 16px，保留使用者縮放；電話欄位使用 `type=tel`，各欄位加上 label 與適當 autocomplete。
- 支援鍵盤 focus-visible，以及 prefers-reduced-motion。

Apple 提供 44pt 觸控與可讀性建議，Android 提供 48dp 觸控建議；本專案的 WebView 先用 48 CSS px 作為共同設計基準，原生封裝後仍須確認實際螢幕映射與觸控範圍。[Apple UI Design](https://developer.apple.com/design/tips/)、[Android accessibility](https://developer.android.com/guide/topics/ui/accessibility/apps)

## 驗證與範圍

- TypeScript 與 Next.js production build 通過。
- 使用真正編譯後的 App 頁面與本機合成 API 資料檢查 UI，未讀寫正式資料庫；preview helper 位於被 gitignore 的 `tmp/`，不會部署。
- 390px 寬度檢查首頁、好友、活動、活動詳情、通知、管理頁、資歷、好友檔案、登入與註冊，均無水平溢位。
- 320px 寬度下檔案頁無水平溢位；主題與補填按鈕高 48px，五個底部選單各寬約 62px、高約 50px。
- 實際切換淺／深色、重新整理保留設定；補填生日／手機聚焦對應欄位；一般會員不顯示幹部工具；模擬 API 503 能看到重新載入提示。
- 320px 寬度配合 125% 根文字大小的個人檔案無水平溢位；電話輸入文字為 16px，自訂職稱保留；合成資料儲存流程成功。選擇「系統」後，實際主題與裝置的 prefers-color-scheme 相符。
- 原生鍵盤、VoiceOver／TalkBack、動態文字、瀏海與手勢區的真機驗收，須待 iOS／Android 封裝完成後執行。網頁 UI 完成並不代表已完成原生 App 上架驗收。

## 給原生封裝階段的接續工作

1. 決定外殼架構後，確保系統 bars／display cutout 的 insets 會正確傳入 WebView；避免原生與網頁各加一次 padding。[Android edge-to-edge](https://developer.android.com/develop/ui/views/layout/edge-to-edge)
2. 原生狀態列圖示亮暗與背景色要同步 `document.documentElement.dataset.theme`；網頁 `theme-color` 不會取代原生 StatusBar 設定。
3. 驗收鍵盤升起後輸入欄位與儲存鈕仍可見；Android 系統返回與 iOS 返回手勢對應頁面歷史；未儲存的表單保留或提示。
4. iOS／Android 分別測試相機拒絕、相簿選擇、App 回到前景、離線／重連，以及重新開啟後的登入與主題設定。
5. 以實機較大文字與螢幕閱讀器檢查截斷、捲動、讀取順序與按鈕名稱；平板版目前沿用 480px 置中會員 App 版型，另排專門的平板體驗驗收。
