# 資歷直接上一級審核與徽章規則

這是本平台採用的核實分工，不宣稱取代獅子會正式任命程序。會員自填資歷、年度核定名冊、AdminRole 管理授權彼此獨立；核實資歷或匯入姓名均不建立管理權限。不審自己，包含 SUPER。

| 待核實資歷 | 有效審核授權 | 精確範圍 |
| --- | --- | --- |
| 會籍、一般分會職務、分會榮譽與顧問資歷 | CLUB_PRESIDENT／CLUB_VICE_PRESIDENT／CLUB_OFFICER／CLUB_FINANCE | 任職的同一分會 |
| 會長、首屆會長 | ZONE_ADMIN | 分會直接隸屬的分區 |
| 分區主席、秘書、財務、顧問 | REGION_ADMIN | 分區直接隸屬的專區 |
| 專區主席、副主席、秘書、財務、顧問 | DISTRICT_ADMIN／DISTRICT_GOVERNOR | 專區直接隸屬的區 |
| 內閣副秘書長、財務長／副財務長、總務長、公關長、資訊長、區特別顧問 | DISTRICT_SECRETARY | 同區 |
| GMT／GLT／GST 協調長 | DISTRICT_CABINET | 同區；不得因此審其他內閣或後代職務 |
| 內閣秘書長 | DISTRICT_GOVERNOR | 同區 |
| 總監、第一／第二副總監、榮譽總監／副總監 | MULTIDISTRICT_ADMIN | 區直接隸屬的複合區 |
| 複合區、國際、基金會、未知職位，或缺少／歧義的任職組織、階層 | SUPER_ADMIN | 明確 GLOBAL、scopeId 為 null；每次須具體例外理由與證明來源 |

資料與安全條件：

- 以資歷的任職組織判斷，不以會員目前分會代替。已綁組織 ID 須與名稱／層級一致；舊資料未綁 ID 僅容許同層級、確切名稱及區別資訊唯一匹配。未登錄、同名歧義、過期／停用組織不自動猜測。
- 嚴格檢查直接 parentId 層級；不跳過缺少的分區／專區，也不讓區級角色概括核實全部後代。歷史 seed 曾使分會直接掛區，其會長資歷需先補正式階層，或由 SUPER 留理由例外核對；不依名冊自動補授權。
- 授權須有效時間內、scopeType／scopeId 與實際組織相符。未來／到期、空範圍、失效帳號均拒絕。一般會員的職稱與現任勾選不參與授權判斷。
- GET 與 POST 共用同一矩陣。POST 必須提供列表的 expectedUpdatedAt；在同一 Serializable transaction 重查帳號、角色、階層及資歷，CAS 更新並寫 ExperienceReviewAudit。退回與 SUPER 核實均必填理由；稽核寫入失敗則整筆回滾。
- 每筆稽核保留審核身分、角色、範圍、理由、被審版本與時間，不複製會員姓名／Email。刪帳後資歷／審核者連結可斷開；理由可能包含個資，應限制存取並依實際保留政策管理。
- 創會人與創會員、導師與導獅保留不同代碼及選項；不將舊值自動換成近義職稱。

徽章規則：只有已知 position 職務、verificationStatus=verified，且任期涵蓋台灣時區目前 7/1 至隔年 6/30 會籍年度，才顯示「本年度已核實職務」。isCurrent 僅是本人標示，不會延長任期、升級徽章或授權；已核實的歷史資歷仍可顯示「已核實」，但不冒充本年度職務。

本輪測試使用隔離 SQL 與合成資料，不代表正式組織階層、有效管理角色、真 RDS 多連線或正式部署已確認。上線須先套包含 ExperienceReviewAudit 的 migration，再部署同版 API／UI；不得把缺階層資料當成區級越權審核的理由。
