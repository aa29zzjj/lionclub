# 待審會員入會年月修正（2026-11-08）

本次為本機程式修正，尚未部署、沒有呼叫正式審核 API，也沒有變更正式會員或資料庫。

## 修正內容

- 網頁及手機 API 的待審名單新增原始 `joinYear`、`joinMonth`、`updatedAt`；不列出已刪除的申請。
- 審核時省略年月欄位會保留原值；明確傳入 `null` 表示未知。核准不再自動以審核當天補入年月。這也改變舊版僅傳 `action` 的行為：原本寫入現在年月，現在保留既有歷史或未知值。
- 年份範圍維持 1900–2100，月份維持 1–12；月份已知時必須有已知年份。清空年份時須明確一併清空月份，不自動刪除已知歷史。
- 新版 App 顯示原始年月、以原值預填，留空表示未知；核准及拒絕都先確認會員、分會與操作內容。送出時包含確認的 `expectedUpdatedAt`、`expectedOrganizationId`，後端拒絕已變更的版本或分會，並以該快照執行更新或刪除。
- App 使用同步操作鎖；未確認的結果或審核錯誤後，必須先重新讀取，不能直接重送。只有收到符合動作及核准年月的明確成功回覆，才會顯示成功並移除申請。
- 保留既有權限、活動／報到／角色歷史及推播交易限制，另補上分會指派歷史的拒絕保護，避免刪除申請時連帶刪除既有指派紀錄。

## 相容與發版限制

- 使用既有可空值年月欄位，本次不需要新增資料庫 migration。
- 請先部署兩端 API，再更新 App。新版 App 遇到缺少歷史年月或版本的舊 API 會停止審核並提示重新讀取，不會猜測日期。
- 舊版網頁表單仍會預填現在年月，並明確送出其表單值；本次沒有修正該網頁 UI 的預設日期。後端只對省略的值保留歷史，不能把網頁明確送出的今天解讀成省略。
- 舊客戶端未提供確認版本時仍可使用原有權限流程；只有提供成對版本／分會快照的客戶端，才能檢查其畫面是否過期。兩種客戶端在交易內都會以重新查得的快照執行狀態變更。
- 尚需由主流程完成 iOS 畫面與實機驗收。隔離 SQL 測試使用單連線 PGlite，不能視為正式 PostgreSQL 多連線併發驗收。

## 本機驗證

- 16 項 focused unit／原生 client 測試通過，包含既有角色／資歷 helper 回歸。
- 34 項隔離 SQL／路由及推播交易回歸通過，涵蓋網頁與手機的歷史值、未知、部分省略、錯誤年月、過期版本、分會變更、無權範圍、指派與活動歷史保護及無歷史申請刪除。
- 全專案 TypeScript 與本次檔案的 diff 空白檢查通過。

所有測試均使用合成帳號與拋棄式資料，不發送正式郵件或手機推播。
