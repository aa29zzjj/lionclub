# 資料保留政策（內部文件）

2026-10-15 制定。對應 Hao 10/14 交接文件 P1：「確認共享活動、稽核文字與匿名歷史保存期；建立刪帳阻擋時的人工處理管道與對外隱私／客服頁」。

## 現狀（已實作的行為）

帳號刪除採**匿名化軟刪除**（`src/lib/account-deletion.ts`），不是整筆資料硬刪除：

| 資料類型 | 刪帳後的處理 | 保留期限 |
| --- | --- | --- |
| 個人識別資料（姓名、Email、電話、生日、大頭貼、分會歸屬、暱稱、LINE ID 等） | 清空／改為「已刪除會員」佔位值 | 立即生效，不保留 |
| 大頭貼照片（S3） | 背景 worker 刪除 | 建立刪除工作後約 6 分鐘延遲，之後盡快清除（受 worker 排程頻率影響，目前每 15 分鐘跑一次） |
| 登入帳號（User）、密碼、驗證／重設 token | 直接刪除（cascade） | 立即生效 |
| 好友關係、封鎖關係 | 直接刪除 | 立即生效 |
| 已發送通知的內文 | 內文改為制式文字（移除原內容） | 立即生效；通知本身的存在（收件人、時間）保留 |
| 自己建立的活動（Event） | **保留**，擁有者顯示為匿名「已刪除會員」 | **目前無預定清除時間（視同永久保留）** |
| 他人對自己建立活動的報名紀錄 | 保留（除了自己尚未報到的報名會被取消） | 同上，永久保留 |
| 活動報到稽核紀錄（EventCheckInAudit） | 保留，記錄報到者與操作者 id（連到已匿名化的會員） | 永久保留 |
| 分會分派歷史（MemberOrganizationAssignment）、資歷審核紀錄 | 保留 | 永久保留 |
| `RateLimitAttempt` | 不涉及特定帳號的個資，純 IP／帳號雜湊鍵 | 48 小時後自動清除（已排程） |

## 政策立場

1. **個人識別資料**：刪帳後立即清除，不保留寬限期、不做備份還原（RDS 自動備份快照屬於資料庫層級的災難復原機制，不是給單一使用者申請找回用的）。
2. **共用的活動／報到／審核歷史**：維持永久保留且匿名化，理由是這些記錄屬於「分會的集體歷史」而非單一會員的個人資料（例如某場活動辦過、誰報到過這件事本身，對分會的稽核與傳承有意義），且已經不含可識別個人身分的欄位。
3. 若未來有會員要求「連匿名化後的活動擁有權／報到紀錄都要完全移除」，目前系統做不到全自動處理，需要透過下方人工管道個案協助。

## 刪帳阻擋時的人工處理管道

會員若因為「持有幹部權限」或「有尚未開始的活動」而無法自行刪除帳號，操作畫面會顯示提示文字，請其先處理完畢再重試。若無法自行解決（例如找不到人接手幹部職位、找不到人接手活動），由 `/support` 頁面公告的聯絡信箱受理，人工協助：

1. 先確認申請人身分（比對帳號 Email 與申請來源）
2. 協助聯繫相關分會幹部處理權限轉移／活動接手
3. 必要時由具 `SUPER_ADMIN` 權限者直接在後台代為撤銷幹部權限，讓申請人能自行完成刪除

## 對外頁面

- `/privacy`：隱私權政策，說明蒐集項目、用途、保留期限、使用者權利
- `/support`：客服聯絡頁，含常見問題與聯絡信箱

兩者皆已連結在登入頁下方，供 App Store／Google Play 審查與一般使用者查閱。

## 尚未自動化、留待未來考慮

- 匿名化後的活動／報到／審核歷史目前沒有任何「幾年後自動清除」的排程，等同永久保留。如果之後法遵或儲存成本考量需要設上限（例如保留 7 年），需要另外設計清除排程並與分會幹部溝通。
- `EmailVerificationToken` / `PasswordResetToken` 中「已使用」或「已過期」的舊紀錄目前沒有定期清理（只有 `RateLimitAttempt` 有排程）；資料量小，暫不影響，但未來資料量變大可以考慮加入類似的每日清理排程。
