## 3. 第二輪額外修正

- 全裝置登入撤銷：重設密碼增加 sessionVersion；「登出其他裝置」驗證目前密碼、只更新當前裝置，其餘失效。舊 JWT 在 migration 後需重新登入。
- 郵件連結安全：正式環境只使用設定好的 HTTPS `NEXT_PUBLIC_APP_URL`，不從任意 request Host 產生含 token 的連結。無設定時安全回報寄信服務尚未就緒。
- 改信箱重複檢查：同時檢查 User／Member 的不分大小寫衝突，避免舊大小寫帳號產生同信箱雙身分。
- 刪活動／調容量與檢查同一 Serializable transaction；有簽到紀錄不得刪除。遇同時更新回 409，不默默刪歷史或超收。
- 頭像清理在刪帳後至少等待 6 分鐘，涵蓋先前 5 分鐘有效的上傳連結；具租約、防重複、失敗重試、精確個人 prefix 保護。未排程或 IAM 未設定時工作仍待完成，不假稱 S3 清空。
- 舊待審會員的拒絕／通過使用交易與狀態檢查；已有活動、報到、通知或權限歷史者不連帶刪除。郵件於成功提交 DB 後寄出。
- 通知發送的有效身分、權限、好友／封鎖及收件人檢查，與建立通知共用交易，避免刪帳後再次寫回個資文字。
- 資歷修改／刪除以狀態條件更新，避免在幹部核實後覆寫；審核攜帶更新時間，內容變動須重載核對。
- 寫入 Cookie、封鎖、通知、個資與資歷操作補可信 Origin 檢查；這是網站 Cookie 契約，不是原生 App 登入方案。

## 7. 可重跑測試與驗證邊界

測試使用真實 TypeScript 路由與 Prisma，在全量 migration 建立的獨立 PGlite PostgreSQL/WASM 資料庫操作。每次獨立建庫；不讀正式 `.env`、不取 Secrets、不連 RDS／SES／S3。Cookie、郵件與儲存空間是測試 adapter，寄信只允許 `example.test` 假地址。

執行入口：

```bash
npm run test:onboarding
npm run test:simulation
npm run test:demo
npm run build
```

本機 UI 模擬：以安全假 DB／Secret 環境建置及啟動 Next，再執行 `npm run simulation:preview -- --port 3196 --frontend-port 3195`，開啟 `http://localhost:3196/__simulation`。角色切換經真登入 API，只有隨機測試裝置 cookie，無正式憑證。假信箱在 `/__simulation/inbox`。服務只綁 loopback、不對外公開；停止服務後資料消失，請勿輸入個資。

本次結果：TS 單元／服務測試 109/109、真 API／SQL 與隔離預覽安全模擬 21/21、既有隔離展示測試 13/13，共 143/143 通過；Next.js production build、Prisma schema 與型別檢查通過。測試故意模擬一次寄信失敗，出現「Password reset email failed」是預期錯誤案例，不是漏修失敗。預覽測試的 SIMULATION_ROUTE_NOT_ALLOWED 也是刻意確認未知 API 被拒絕。

手機 UI 抽查：390×844 及 320×740 CSS px；月曆 390px 七天完整可見，320px 只在月曆區內橫滑，頁面寬度不溢出。確認前後月份／今天、點日期顯示兩場活動、活動詳情入口；6 月與 7 月表單提示分別顯示 25-26／26-27；有效歷史 QR 重開與 Escape 回焦；人工核對補登由 0/1 更新至 1/1，成功訊息保留；通知標已讀及獨立封鎖名單可開啟。日夜畫面存證在 `output/acceptance/2026-10-14-fixed/`。

測試過程另修正隔離預覽代理未放行 Next 動態頁 `%5Bid%5D` chunk 的問題，避免合成活動詳情出現 ChunkLoadError；這是測試代理缺口，未把它誤判為正式資料庫錯誤。
