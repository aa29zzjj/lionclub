## migration 與發布

1. 確認要部署的 main SHA 與現行 migration 清單；先備份並驗證可還原，再於非正式 DB 執行 `prisma migrate deploy`，核對新增 `20261023110000_event_tags`。
2. 非正式通過後，正式套用依既定核准／發布流程，不需重新把 v2 增量 ZIP 覆蓋進 main。本輪沒有由代理直接套正式 DB。
3. migration 是加法欄位 `Event.tags TEXT[] NOT NULL DEFAULT []`，舊活動不猜填標籤，與會員名冊／權限無關。
4. **未遷移時已有相容保護**：既有活動可讀、無標籤活動可發布／編輯／報名；UI 暫停標籤，帶標籤操作回 503 並原子回滾。
5. 套用成功後下次查詢自動啟用標籤。保留 schema 的 `@ignore` 與 `event-tags.ts` 能力檢查；沒有確認所有環境遷移前不要改回無條件 ORM 讀寫。
6. 回退程式時先保留新增欄位；勿直接 DROP COLUMN 或回滾整庫而丟失後續活動。任何正式 DB 操作仍依備份／核准流程。
