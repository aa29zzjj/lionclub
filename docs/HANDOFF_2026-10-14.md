## 一、重大問題修復

| 問題 | 說明 |
| --- | --- |
| **正式站曾經壞掉** | Hao 10/13 的 QR-only 版本已自動部署上線，但對應的 migration（`20261013042000_central_onboarding_assignment`）當時還沒套用到正式 RDS。這代表部署後、我發現並修好之前的這段時間，正式站的註冊功能是壞的（寫入新欄位會直接報錯）。已立即套用 migration 並實測註冊流程恢復正常。 |
| **寄信全部用「不等待」的寫法，實際上常常沒寄出** | 原本 `void sendSesEmail(...)` 這種寫法沒有 `await`，在 Amplify 的 serverless 環境下，API 回傳 response 後常常直接被凍結/回收，導致信在真正送出前就被打斷。已經把所有寄信（歡迎信、驗證信、審核通知信）都改成 `await`，實測寄信會真的送出了。這應該也解決了你之前可能遇過「幹部審核通知信不穩定」的問題。 |

## 二、本次新增功能

| 功能 | 說明 |
| --- | --- |
| 速率限制 | 登入、註冊、忘記密碼、檢舉都加上以 IP 為單位的限流（資料庫實作，無狀態環境也能用） |
| Email 驗證 | 註冊、改 email 會寄驗證信；未驗證會在個人檔案顯示提醒並可重寄 |
| 帳號刪除 | 會員可自行刪除帳號（需輸入密碼確認），若持有幹部權限或有未開始的活動會先擋下 |
| 封鎖／檢舉 | 會員檔案頁可封鎖（自動解除好友關係）或檢舉，檢舉送到 `SUPER_ADMIN` 專用審核頁 |
| 正式名單批次匯入 | `/admin/member-assignment` 新增 CSV 貼上匯入，先預覽差異（含錯誤列）才送出，逐筆走原本的分派安全檢查 |
| 暱稱欄位 | 個人檔案可設暱稱，好友列表、首頁好友動態、通知收件人選單、會員檔案頁都會優先顯示暱稱 |
| **會員證報到功能** | 原本「數位會員證 QR」只是裝飾，跟好友 QR 功能重複。現在活動建立者／幹部可以在活動頁「掃會員證報到」，掃會員的 QR 直接核對報名狀態並標記簽到，報名名單會顯示已報到／未報到 |
| 註冊「原所屬分會」改成可搜尋下拉 | 原本是純文字輸入，現在會即時搜尋正式分會清單（353 筆，含區代碼）並顯示下拉選單，仍可手動輸入清單外的名稱 |

## 五、需要 Hao 接手處理的事項

1. **舊角色 scope 盤點**：Hao 自己在 10/13 文件裡提過，舊的管理 helper 仍把「非 SUPER 的空 scope」當全域處理，角色管理 GET 也還缺完整 `validFrom` 過濾，未生效角色可能提前取得名單。這塊我這次沒有動，需要 Hao 自己盤點收斂。
2. **伺服器 Session 全裝置撤銷**：目前改密碼、刪除帳號都只處理當前 session／資料庫記錄，沒有讓其他裝置上還登入著的 JWT 失效的機制。如果要做「踢掉所有裝置」這種功能，需要額外設計 session 版本號或黑名單機制。
3. **檢舉後續處理動作**：目前「檢舉管理」只能標記已處理／駁回，沒有串接實際的停權/封鎖動作（例如自動把會員狀態改 SUSPENDED）。要不要做成自動化、還是維持人工介入，需要先決定管理流程。
4. **會員證報到功能的 UX 回饋**：這是全新功能，我只做了基本版（掃 QR → 核對報名 → 標記簽到）。實際拿去現場用過後，如果有工作流程上的調整（例如要看到即時簽到人數、要能手動補登不會用 QR 的人），麻煩回饋給我們調整。
5. **App Store 上架**：用 Hao 自己寫的 `npm run app-store:check` 腳本檢查，58 項目前只完成 10 項。原生 iOS/Android 專案、隱私權政策頁、客服頁、素材準備都還沒開始，這塊工程量最大，需要另外排時間規劃。

## 六、驗收建議

部署後建議至少跑一次：
1. 用示範帳號登入 → 確認速率限制不會誤擋正常使用
2. 跑一次完整註冊流程 → 確認收到驗證信、「原所屬分會」下拉搜尋正常
3. 發布一個活動、報名、用「掃會員證報到」實際測一次簽到
4. 到個人檔案設一個暱稱，確認好友列表等處顯示正確
5. 用測試帳號跑一次帳號刪除流程（注意：這是真的會刪除資料，建議用專門的測試帳號）
