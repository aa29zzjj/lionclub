# 會長／會員免登入體驗測試指南（2026-10-13）

這兩個入口提供最新前端搭配合成 API 的操作體驗，不需要登入，也不使用正式帳號、密碼、會員名單、RDS、S3 或 SES。畫面內姓名、分會、邀請、活動及異動紀錄皆為示範資料；請只輸入虛構內容，不要填真實聯絡資料或密碼。

下列公開網址是本次臨時測試入口，電腦、前端、合成 API 與隧道都須持續運行；重啟隧道後網址會改變。`localhost:3103`／`localhost:3104` 是本機備用入口，只能在啟動伺服器的電腦開啟。

| 入口 | 網址 | 模擬身分 |
| --- | --- | --- |
| 會長 | [會長體驗](https://florists-outlined-aus-recovery.trycloudflare.com/profile) | 體驗會長，具有兩個示範分會的會長授權 |
| 會員 | [會員體驗](https://competitors-swaziland-communities-meetup.trycloudflare.com/profile) | 初始為體驗會員；一般會員權限 |

會長同時具「AI臺科大獅子會（體驗）」與「示範正式分會（體驗）」兩個明確分會授權，才能體驗跨會分派；不是 SUPER_ADMIN，也不代表所有會長都能跨分會。正式服務仍要求來源與目標都在實際管理範圍內。這兩個分會名稱在此環境僅代表體驗資料，不是正式會員名單。

每頁頂端的「分會長測試 · 合成資料」或「會員測試 · 合成資料」可辨識目前入口；「測試說明」會開啟 `/demo`，不需要登入。

## 共享資料與重設

- 兩個入口共用同一份記憶體合成資料；會長改派後，會員入口重新整理即可看到更新。
- 會員入口免登入，但不是每人獨立的沙盒。註冊成功會把「目前體驗會員」切換為新建合成會員，權限仍為一般會員；其他人註冊、改資料或重設，也會影響正在測試的人。
- 建議由一人操作會長入口、一人操作會員入口，依序測試並記下會員姓名。換一組情境前先協調重設，避免互相覆蓋。
- 兩個入口頂端的「重設」都可重設全部共享體驗資料，對應 `POST /api/demo/reset`；重設後會員回到初始「體驗會員」、中央暫存分會與待分派狀態。伺服器重新啟動也會重新建立合成資料，這些操作不影響正式網站。
- 分會分派不是即時推播；分派完成後請重新整理會員頁。淺／深色偏好保留在各裝置，不隨共享資料重設。

## 建議先跑的完整流程

1. 在會員入口開「我的檔案」，確認可使用會員功能，但有「正式分會待名單核對」提示，且沒有幹部工具。
2. 在會長入口開「幹部工具 → 入會邀請」，選 QR 效期 1／3／7／30 天（預設 3 天），產生新的邀請 QR。邀請連結應前往會員入口，不能跳到會長入口；現場活動請在活動前或當日產生。
3. 掃描步驟 2 最新產生的 QR，填寫虛構姓名、`member-demo-01@example.test` 與至少 8 字元的示範密碼，例如 `DemoOnly88`。此密碼只供示範表單，不是正式登入憑證，也不會儲存。直接開一般 `/register` 不應繞過 QR 驗證；沒有有效 QR 時請回會長入口取得新邀請。
4. 註冊完成後進入會員頁：新建會員可以直接使用，暫存中央分會且待分派；不能出現「等待入會核准才能使用」。體驗角色仍是一般會員。
5. 會長開「會員分會分派」，搜尋剛填的虛構姓名；選「示範正式分會（體驗）」、填寫核對原因，閱讀影響說明並勾選確認，再送出。
6. 會長查看成功提示及分派歷史。會員入口重新整理「我的檔案」，確認所屬分會已更新、待核對提示消失；會員仍沒有幹部工具。

新註冊的「原所屬分會」只供名單核對，不能直接決定加入分會或取得管理權限。體驗中的自動身分切換由合成資料實現，不代表已測試正式 Cookie 登入。

QR-only 的意思是新註冊需由有效邀請 QR 開啟；沒有手動邀請碼測項。掃描或完成平台註冊不證明正式獅子會會籍已被驗證。QR 到期只影響新的註冊，既有帳號仍可使用；沒有 30 天試用／自動停權。

## 必驗情境

| 測試 | 操作與預期 |
| --- | --- |
| 有效 QR | 合成邀請 token 通過驗證後可填資料；註冊送出時仍再次驗證；實際加入中央暫存會，邀請來源不直接決定目的分會 |
| 沒有邀請 | 直接開一般 `/register`，只能看到需要有效 QR 的說明，不能建立帳號；API 缺有效 token 也必須拒絕 |
| 無效／過期 QR | 把 token 改成無效值，或使用已過期合成邀請；停在邀請錯誤畫面，可重新驗證或取得新 QR，不能直接進入可送出的註冊表單 |
| 邀請效期 | 預設選 3 天；1／3／7／30 天產生的邀請有相符到期時間。QR 到期或停用後不能新註冊，但先前已建立的合成會員仍可使用 |
| 舊 PENDING 與新待分派 | 「審核新會員」只處理舊 PENDING 案例；新註冊是 ACTIVE＋NEEDS_ASSIGNMENT，出現在「會員分會分派」，不需要再核准才能使用 |
| 同分會核對 | 待分派會員保留目前中央分會，填原因並確認；狀態改已確認、寫入歷史；再次選同一分會顯示「此分會已確認」且不能重複送出 |
| 跨分會分派 | 只能選授權範圍內的兩個分會；填 2–1000 字原因並明確勾選；分派前可看到舊會角色／邀請處理說明，新會不自動授權 |
| 分派紀錄與會員頁 | 首次中央註冊紀錄顯示「中央註冊」／「系統」；後續分派有來源、目標、原因與處理人；會員重新整理後的分會與核對狀態一致 |
| 版本衝突 | 兩個會長分頁先開同一會員；第一頁完成分派後，第二頁用舊資料送出應 409。重載最新資料、保留目標與原因，重新核對前不能盲目重送 |
| 一般會員權限 | 會員「我的檔案」沒有幹部工具；直接開 `/admin/invites`、`/admin/pending-members`、`/admin/pending-experiences`、`/admin/roles`、`/admin/member-assignment` 都不能操作或顯示後台聯絡名單 |
| 日夜與表單 | 依序切系統／淺色／深色；重新整理保留偏好，錯誤文字可讀；手機補填、生日、下拉選單、儲存與底部導覽在窄螢幕可操作 |

測試舊 PENDING 的核准／拒絕前，請記下該合成案例名稱；核准後應退出待審核名單。PENDING 的狀態不能與「可正常使用但正式分會待核對」混為一談。

## 給 Jerry 的 API 權限核對

一般會員入口即使直接呼叫 API，下列後台接點也應回 `403`，且不回傳邀請 token、會員聯絡名單或分派歷史：

- `GET/POST /api/invites`
- `GET /api/admin/pending-members` 及其審核 POST
- `GET /api/admin/pending-experiences` 及其審核 POST
- `GET/POST /api/admin/roles` 與撤銷角色 DELETE
- `GET /api/admin/member-assignments` 與會員分派 detail GET／POST

`POST /api/demo/reset` 是這次合成體驗專用例外，兩個入口皆可重設，不屬於正式管理 API。

一般會員對非自己建立、非授權管理的示範活動，`GET /api/events/[id]/registrations` 也應 `403`。活動建立者本來就可查看自己活動的名單，不能把此資格誤判成越權。

會長也不是全域管理者：範圍外的會員／目標分會 ID 不得讀取或分派成功；改 URL 或 POST payload 不能擴張權限。不能自行改派本人、不能把 PENDING／停權會員當成 ACTIVE 改派。合成測試只能驗證此 proxy 的模擬結果，正式授權仍須以真實 API 與 PostgreSQL 驗收。

會後正式名單核對應由授權後台處理，不用直接改資料庫整批搬人。自行填寫的原分會只是參考，不能自動變成正式分派；大量名單的批次作業仍是後續規劃。

## 測試邊界與回報

合成代理可由 `npm run demo:preview -- --origins-file tmp/demo-origins.json` 啟動；該本機 JSON 的 `chair`、`member` 應填入兩個實際 HTTPS 隧道 origin。無此設定時，邀請／合成圖片網址預設指向 localhost，僅適合本機測試。不要把 production origin 或帳密填入此檔。

這裡適合共同檢查操作順序、文字、頁面串接、角色入口及合成資料的變更。正式 Cookie／全裝置撤銷、真正併發交易、RDS migration、SES 寄信、S3 上傳、正式 QR 與 iOS／Android 原生權限不在此環境的驗證範圍。大圖上傳在體驗環境有額外限制，請使用小張合成圖片；被拒絕不等於正式 5 MB 上傳規則有問題。

本輪 QR-only 已通過後端 56 項、合成體驗／代理 13 項自動測試與 production build。公開 UI 已驗證缺少邀請不提供註冊表單、有效 QR 可完成立即開通、短效 QR 選項與會員權限隔離。這些不包含正式資料庫或 Apple／Android 原生驗收；公開體驗網址不代表正式 RDS／Amplify 已完成部署。
