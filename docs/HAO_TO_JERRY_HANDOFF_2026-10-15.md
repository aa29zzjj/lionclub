## 2. 核定名冊與匯入安全

核定依據為使用者於本對話表示「名單核對無誤」，範圍是已提供照片中可見的資料。來源涵蓋第 1-9、51-62 頁；第 10-49 頁未提供，第 50 頁僅局部，第 63 頁為活動計畫而不納入。不可將這份資料宣稱為完整全冊。

### 組織、任職、帳號與權限各自獨立

組織隸屬使用明確的來源 key 與 parentKey；年度任職另外保存於 AnnualAppointment，以 RosterImportBatch 記錄核定批次。年度是名冊列載年度，未捏造個人任期起訖。歷任、榮譽或顧問列載不會被全部當成現任行政幹部。

不需先補 Email。AnnualAppointment 不關聯 User／Member；匯入不寫入 User、Member、MemberExperience 或 AdminRole。本人身分確認、帳號連結、資歷核實及管理授權是四項獨立後續作業。

### 必須由操作人完成的 ID 映射

- 每個來源組織必須明選 existing 或 create，填入明確 targetId 與正式名稱；existing 另外核對 DB 原名、目前父層、層級、區別與有效狀態。
- AI臺科大與台北科大不得合併；「紳德」、「僑商」等來源原文不得用近似名稱自動套用其他分會。
- 新增專區／分區，以及把既有分會移到核定分區，會改變後代權限範圍。Jerry 必須逐筆核准 reparent 差異，不能只核總筆數。
- 缺少祖先、錯誤層級、停用節點、循環、模糊比對或無時區的核定時間均拒絕。已完成針對性獨立複查。

### 工具保護

預設離線，只產生預覽；不自動讀取 .env、ambient DATABASE_URL 或 AWS Secrets。使用 --inspect-db 才做明確目標的唯讀檢查；寫入另須 --apply、已審核 planDigest 與資料庫 label 三項明確確認。

正式套用以 Serializable 交易重讀組織與祖先，再比對預覽摘要；任何失敗整批回滾。同批同來源重跑不重複寫入；同批變更來源會拒絕，年度／組織／來源列另有唯一索引。日誌只輸出摘要及筆數，不印具名明細或連線字串。

## 3. 權限、審核與顯示修正

### 官方活動

官方活動現在包含「本分會」在內，都需要有效 AdminRole；一般會員的建立表單預設個人活動。伺服器會再次驗證角色時間、scopeType、組織有效性與真實階層，不能靠前端欄位或建立者身分繞過。

建立及編輯在交易內重查授權。官方活動的 host 必須是對應層級的實際組織；僅對個人活動保留建立者管理權。官方授權到期或撤回後，不因最初是建立者而繼續管理官方活動。

既有 ZONE／REGION／DISTRICT 官方活動若仍錯掛分會 host，管理與出席操作會安全拒絕；觀看／報名維持既有規則。Jerry 應逐筆確認真正主辦組織，再受控修正舊資料，不能批次猜測升級。

### 資歷核實分工

這是平台的核實分工，不取代正式任命程序。角色一律須為有效且精確管轄的管理授權；包含最高管理者在內，所有人都不得審核自己的資歷。

| 待核實職務 | 具有效授權的審核者 | 管轄範圍 |
| --- | --- | --- |
| 會籍、一般分會職務／榮譽 | 分會會長、副會長、幹部或財務角色 | 任職的同一分會 |
| 會長、首屆會長 | 分區管理者 | 分會直接上層分區 |
| 分區職務 | 專區管理者 | 分區直接上層專區 |
| 專區職務 | 區管理者或總監 | 專區直接上層區 |
| 明列的區內閣職務 | 區秘書長 | 同區；依職位白名單 |
| GMT／GLT／GST 協調長 | 區內閣角色 | 同區；限明列協調長 |
| 區秘書長 | 總監 | 同區 |
| 總監、一副／二副、榮譽總監／副總監 | 複合區管理者 | 區直接上層複合區 |
| 未知、複合區／國際／基金會，或階層缺漏 | 明確全域最高管理者 | 個案例外；必填理由與證明來源 |

以資歷的「任職組織」判斷，不以會員目前分會替代。缺上層或同名歧義不猜測、不放寬區級權限。核實採 expectedUpdatedAt 版本檢查；審核、更新與 ExperienceReviewAudit 稽核同交易，稽核失敗即回滾。退回或全域例外必填理由。

### 本年度徽章與工具入口

「本年度已核實職務」須為已知職位、已核實，且任期涵蓋台灣目前會籍年度。自填 isCurrent 不延長任期、不升級徽章、不給權限。區級僅審核角色顯示資歷工具，不因此取得邀請或角色管理功能。
